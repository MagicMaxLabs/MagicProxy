Обычный VPN-клиент заворачивает через сервер **весь** трафик системы. MagicProxy
работает точечно: включаешь его в нужном профиле Chromium — и **только этот профиль**
ходит в интернет через твой сервер. Соседние профили и все остальные программы
работают как обычно.

Под капотом полноценный VLESS-клиент с Reality и XTLS-Vision, только вся эта кухня
спрятана за одной кнопкой.

## Зачем это нужно

- Держать рабочее, личное и «под задачу» в разных профилях с разными выходами в сеть.
- Не заворачивать в туннель весь компьютер — только браузер, только там, где надо.
- Удобно пользоваться своим VLESS-сервером прямо из браузера.

**Чем отличается от v2rayN, Hiddify и подобных:** те проксируют всю систему.
MagicProxy — один профиль браузера, и спокойно уживается с уже установленным клиентом.

## Установка

1. Скачай **[MagicProxy-Setup.exe](https://github.com/MagicMaxLabs/MagicProxy/releases/latest)**
   и запусти. Внутри уже всё есть — сетевое ядро включено, интернет для установки не
   нужен, права администратора тоже.
2. Добавь расширение в браузер *(в Chrome Web Store на модерации — пока ставится
   через «Загрузить распакованное», см. ниже)*.
3. Открой 🪄 на панели, вставь ссылку на свой сервер, нажми **Включить**.

<details>
<summary>Пока расширения нет в магазине — как поставить</summary>

Скачай `MagicProxy-windows-amd64.zip` из релиза и распакуй. Затем открой
`brave://extensions` (или `chrome://extensions`), включи **Режим разработчика** и нажми
**Загрузить распакованное**, указав папку `extension`.

</details>

> **Windows покажет синее окно «Windows защитила ваш компьютер».** Это обычное
> предупреждение для программ без платной цифровой подписи. Нажми **«Подробнее» →
> «Выполнить в любом случае»**. Хеш файла для проверки — в `SHA256SUMS.txt` рядом с
> релизом.

## Поддерживаемые протоколы

VLESS (REALITY, XTLS-Vision, ws, grpc, httpupgrade), VMess, Trojan, Shadowsocks
(+ShadowTLS), Hysteria2, Hysteria, TUIC, AnyTLS, WireGuard, SSH, а также обычные
апстрим-прокси SOCKS5, SOCKS4, HTTP и HTTPS — с авторизацией и без.

Ссылки импортируются как есть: `vless://`, `vmess://`, `trojan://`, `ss://`,
`hysteria2://`, `hysteria://`, `tuic://`, `anytls://`, `ssh://`, `socks5://`,
`http(s)://` и base64-подписки. Для WireGuard и ShadowTLS в редакторе есть шаблоны.

## Почему две части, а не одно расширение

Расширение Chromium физически не может само передавать трафик по VLESS: `chrome.proxy`
понимает только HTTP и SOCKS, а песочница MV3 не умеет открывать сырые сокеты и
слушать порт. Поэтому VLESS говорит небольшой фоновый компонент (его запускает сам
браузер), а расширение направляет в него трафик **своего профиля**.

Единственная чисто браузерная альтернатива — Direct Sockets в Isolated Web Apps —
обычным пользователям вне ChromeOS недоступна, а Brave её намеренно отключает. Так что
это не компромисс, а единственный работающий путь. Подробно:
[docs/HOW-IT-WORKS.md](docs/HOW-IT-WORKS.md).

## Приватность и безопасность

Ни аккаунтов, ни телеметрии, ни аналитики. Данные твоих серверов лежат локально в
профиле браузера и никуда не отправляются — у проекта нет серверов. Расширение не
запрашивает доступ к сайтам и ничего не внедряет в страницы.

Честно о границах — что защищает, а что нет (анонимность, WebRTC, DNS, хранение
паролей): **[SECURITY.md](SECURITY.md)**. Политика приватности:
**[PRIVACY.md](PRIVACY.md)**.

## Совместимость с другими клиентами

**В обычном режиме прокси конфликта нет.** Ядро слушает свой локальный порт (не
дефолтные 10808/10809), а `chrome.proxy` переопределяет системный прокси только для
своего профиля. Проверено с Clash Verge: когда MagicProxy выключен — трафик идёт через
Clash, когда включён — через MagicProxy. Всё как ожидается.

> ### ⚠️ Режим TUN в другом клиенте несовместим
>
> Если Clash Verge, Hiddify, v2rayN или sing-box работают в режиме **TUN**, они
> поднимают виртуальный адаптер и забирают **весь** трафик системы — включая
> исходящее соединение MagicProxy к твоему серверу. Получается двойное
> проксирование, и протоколы, которые проверяют подлинность сервера, ломаются.
> Для VLESS+REALITY это выглядит так:
>
> ```
> connection: open connection to ... using outbound/vless[proxy]: reality verification failed
> ```
>
> **Что делать:** переключить второй клиент в обычный режим прокси, либо добавить
> адрес твоего сервера в его список исключений (bypass).
>
> MagicProxy распознаёт эту ситуацию: если ядро падает с такой ошибкой, а в системе
> есть активный TUN-адаптер, в логах появится объяснение причины по-русски, а не
> только сообщение ядра.
